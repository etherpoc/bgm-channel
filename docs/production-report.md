# 作業用BGM YouTubeチャンネル 制作レポート

最終更新: 2026年6月14日

---

## 1. プロジェクト概要

AIを活用して作業用BGM(インスト)のYouTubeチャンネルを制作する。動機は「自分自身がこの種の音楽を作業中によく聞くから」であり、これは単なる収益目的ではなく**自分が顧客=品質判断を自分でできる**という強みになる。

このプロジェクトは、より広い目標(人との対話を最小化できる・最終的にシステムで自動化できる・詐欺まがいでない稼ぎ方)の一環として位置づけられる。

### 重要な前提認識

- 音楽の広告単価(RPM)は低めなので、**広告収入だけを当てにしない**。メンバーシップ・他の自製品への導線など収入の分散を前提とする。
- このチャンネルは「直接の稼ぎ頭」というより、ブランド資産・集客口としての価値も大きい。

---

## 2. 全体を貫く戦略原則

検討を通じて繰り返し確認された、すべての工程に共通する原則:

- **2026年のプラットフォーム(Google検索・YouTube)は「無人の量産AIコンテンツ」を罰し、「人間の方向性+独自性+低い法的リスク」を残す**方向に揃っている。YouTubeの「inauthentic content(非真正コンテンツ)」ポリシーが代表例で、テンプレ量産・低変化・スケールで複製可能なものが対象。罰則はチャンネル全体に及ぶ。
- したがって**自動化するのは「ドラフト/素材まで」。最後に人間が独自性とキュレーションを一手間加える**。差別化になる2割は人間が担う。
- **手で1サイクル回してから仕組み化する**。回したことのないプロセスは自動化できない。
- 「自分が聞きたい音を選ぶ」という行為そのものが、量産判定を回避する**人間のキュレーションの核**になる。

## 3. 音楽制作(決定事項)

### 使用ツール: Google Lyria 3

選定理由:
- **法的リスクが低い**: ライセンス済み学習データ + SynthIDウォーターマーク。
- **エコシステムの一貫性**: GCPに慣れているため、Vertex AI / Gemini API経由で将来の自動化パイプラインに乗せやすい。
- 入口は2つ。まず手触りを掴むなら **Google Flow Music**(Lyria 3ベースの無料スタジオ)、パイプライン前提なら **Vertex AI / Gemini API**。

制約と対策:
- **最大3分**の尺制限 → 同じ世界観で複数トラックを生成し、繋いで長尺ミックス化する前提で設計。

### プロンプトの型

```
[genre/style] + [mood] + [tempo/BPM] + [instruments] + [texture/production] + [movement/loopability]
最後に必ず: instrumental, no vocals
```

- Lyria 3は**ネガティブプロンプト**が使えるので「入れたくない要素(急な展開・ボーカル・うるさいドロップ等)」を別途指定すると精度が上がる。
- 英語プロンプト推奨(解像度が高い)。
- **一度に1変数だけ変える**(何が効いたか分かるように)。

### 進捗と次のアクション

- 初手から満足度の高い音が生成できた(良いスタート)。
- ただし現状は「当たりプロンプト1個」で、**なぜ当たったかは未分析**。
- 満足度が高い今こそ、**当たったプロンプトから1変数だけ変えた派生を3〜4個試し、「正解の輪郭(何が本質的に効いているか)」を逆算で掴む**のが最適なタイミング。
- 1個の名曲より「同じ質を再現性をもって出せる型」の方がチャンネルには価値がある。

## 4. 映像制作(決定事項)

### 制作レベル: レベル2(アニメーションループ)

3つのレベル(静止画+軽い動き / アニメーションループ / 生成動画)のうち、**工数と効果のバランスが最も良いレベル2**を採用。「静止画1枚に音を乗せただけ」は量産判定リスクが高いため避ける。

### 静止画: Midjourney(Basic Plan利用中)

- **Basic Planは商用利用OK** → 収益化チャンネルに使える。
- 当面はWeb UI(midjourney.com)で手作業生成。API/自動化は世界観が固まってから。
- 注意点:
  - BasicにはRelaxモード(無制限のゆっくり生成)が無い → Fast時間を使い切ると停止。枚数が足りなくなったら上位プランを検討。
  - BasicにはStealthが無い → **生成画像とプロンプトは他ユーザーから見える**。世界観を真似されたくない段階になったら上位プランを検討。

### モーション(静止画→動画)の候補

| ツール | 位置づけ | 備考 |
|---|---|---|
| **Veo 3.1**(Vertex/Gemini) | 本命 | Lyriaと同じGoogle系・SynthID・seamless extendでループ向き。ただし音声同期機能は自前音源があるため無駄。試行はLite等の安価版で。 |
| **LTX-2.3 / Wan 2.7**(OSS) | コスト/自前運用 | Apache 2.0で権利が最もクリーン。大量生成のコストを抑えやすい。 |
| **Seedance 2.0 Pro** | 手軽な商用枠 | 商用ライセンス付き・ウォーターマークなし。 |
| Sora 2 | **回避** | 2026年9月24日にAPI停止予定。上に作り込まない。 |

### ループ運用

- 単発クリップは長くても15〜20秒で頭打ち → それ以上はスティッチ(繋ぎ)前提。
- 流れ: Midjourneyでキービジュアル(音の世界観と揃える) → image-to-videoで数秒〜十数秒のループ素材生成 → **DaVinci Resolve(無料)**で音の長尺に合わせて繰り返す。
- **Midjourneyのオリジナルキーフレーム + 世界観の一貫性(seed/style使い回し)が、量産判定回避の核**。

## 5. フォーマット・尺(決定事項)

- **長尺ループが基本**(視聴維持時間が伸びる・リピート再生・広告余地)。
- ただし「同じ数秒を繰り返すだけ」は量産判定に近づくため、最小限の起伏をつける:
  - 音側: 似た雰囲気の複数曲を繋いで移り変わるミックスにする。
  - 映像側: 完全静止ではなく、ゆっくりした動き(雨・光の明滅・湯気等)を入れる。
- 構造: **短い動画ループ(15〜20秒)を映像として繰り返し + その上に複数曲を繋いだ30分〜1時間の音声ミックス**。映像は短く、長さは音声側で作る。
- **最初の1本は30分程度**から。尺が長いほど繋ぎ目や粗が目立つので、まず30分で「繋ぎが自然か」「ずっと聞けるか」を確認してから伸ばす。

## 7. 未決事項・ネクストアクション

### いますぐ決めること(ユーザー判断)

1. **音楽の方向を確定**(lo-fi / アンビエント / ソロピアノ / Liquid DnB / ミニマル等)。当たったジャンルはどれか。
2. **映像の世界観を確定**(音の方向に寄せるか、あえて別の絵をあてるか。具体的な情景イメージの有無)。

### 確定後の流れ

3. 当たったプロンプトの派生を試し、再現可能な「型」を掴む。
4. Midjourneyでキービジュアルを作成 → Veo 3.1 Lite等でループ素材を1本生成 → 繋ぎ目とモーションの自然さを確認。
5. **最初の30分動画をエンドツーエンドで手作業で完成させる**(音ミックス + 映像ループ + 尺合わせ)。
6. 公開前チェックリストを通して1本公開。
7. 手作業で見えた反復部分を抽出 → CLAUDE.md + Skill化 → plugin化 → headless/CI(人間マージ必須)で段階的に自動化。

### 記録の習慣(資産化)

- 当たったプロンプト全文・seed・生成日時・どのバリエーションが良かったか・気に入った理由を必ず保存。
- これは再現性の担保であると同時に、将来のブログ記事化(独自データ)と自動化の資産になる。
